Automatic alignment and metric implementations

The previously used phrase 'official matching' means the automatic alignment produced by the evaluation library, not manually annotated ground truth. MUSTER converts GT into an HMM and the prediction into a performance-like SPR. ScorePerfmMatcher initializes correspondence, ErrorDetection marks errors, and RealignmentMOHMM performs local realignment. The evaluator retains the first correspondence for each GT ID, counts repeated correspondences as extra notes, and then computes error rates.

Pitch/Miss denominators use GT notes after truncation and deduplication of simultaneous unisons; Extra uses predicted SPR events. OnsetER = RCC / matched GT notes; OffsetER = unequal normalized end-tick count / matched GT notes. MeanER averages those five rates. See each case's detail.txt for complete records.

Onset RCC measures scaling and correction costs on successive inter-onset intervals. Offset first anchors matched predicted onsets to GT onsets, then maps an end tick using neighboring matched onsets and their rhythmic scale ratios. Candidates at the same onset also use pitch distance; the ending uses the latest available ratio, with integer-tick arithmetic. Consequently, identical raw durations can still incur offset errors, while different raw durations can become correct after normalization.

SS builds DTW correspondence using XOR costs between 128-dimensional pitch-bit vectors of onset groups. Within paired groups it matches same-staff, same-spelling notes first, then identical pitches, then enharmonic equivalents; remaining notes become miss/extra. Missing notes and certain cross-staff matches bypass some attribute comparisons, so lower duration/spelling/stem counts do not automatically indicate better overall output.

if abs(a.duration.quarterLength - b.duration.quarterLength) > 1e-3:

SS spelling treats an explicit natural and an absent accidental as equivalent. Accidental visibility and visual clef/key optimization are not fully covered by these 12 metrics. All six SS rates here use n_Note as denominator, consistent with the original table.

Excerpt playback, score cursor, and context

Every existing single-metric example includes one additional measure on either side, clipped at file boundaries. GT and prediction expand around their own respective measure ranges. Performance MIDI is located against the same GT context through input-MIDI-to-GT automatic matching. GT/prediction cursors use the playback timeline of their own excerpts. The performance-MIDI cursor is an approximate GT reading aid based on automatic matching and monotonic interpolation; it does not replace metric note correspondences.

GT, prediction, and performance MIDI use the same piano sound source. Original performance MIDI is rendered in full before cropping, retaining its timing, dynamics, controllers including pedal, and pre-excerpt sustain state. XML excerpts are exported to MIDI with Verovio, retaining numeric tempo indications; passages without a numeric tempo default to quarter note = 120. Browser pitch-preserving 0.5x/0.75x playback keeps the original red/blue error colors, while gold indicates playback position only.
