Coordinate convention: local is a zero-based quarter-note offset within a measure. local=2 is not 'beat 2': in 4/4 it starts beat 3, while local=2.5 is the second half of beat 3. Earlier wording that called these beat 2/2.5 was inaccurate. duration/quarterLength denotes length; onset denotes start; off/end denotes ending position. The P number in a note ID is an XML part, not a staff number: GT has one part containing two staves.

GT becomes an HMM with chord/ornament states; the prediction becomes SPR with start/end times. The value 0.01 is the matcher's initial secPerQuarterNote parameter, not a per-note matching tolerance. ScorePerfmMatcher uses pitch likelihoods, inter-onset intervals, state transitions, and tempo tracking to find a Viterbi path, allowing substitutions, insertions/repetitions, and skips. It does not simply match each nearest identical pitch.

Backtracking then recovers the state sequence. GetFmt1ID selects a candidate reference ID within the chosen state using pitchDiffProb. Source: ScoreFollower_v170503.hpp, ScoreFollower_v170503.hpp.

ErrorDetection subsequently performs cluster/note matching. For identical-pitch candidates it favors onsets nearer refT; remaining reference/prediction sequences are paired and classified using pitch-error likelihoods. 2. Stem fidelity does not establish readability

The selected quotation concerned the GT32 miss figure; the comment about matching stem directions referred to the earlier GT60 stem figure. These dimensions must be distinguished. In GT60, M2ST stems match GT more closely, yet dense high-note ledger lines under the bass clef are difficult to read. The new model's downward stems bring beams closer to the staff and can look more compact. It is reasonable that the stem score fails to reflect this reading experience. Both predictions still use bass clef on the lower staff; neither reproduces GT's treble-clef optimization.

The original score simply compares direction strings:

<code class="language-python">            if a.stemDirection != b.stemDirection:
                errors[ScoreErrors.StemDirection] += 1
</code>

To demonstrate that identical stem scores can coexist with very different readability, the following illustration changes only the lower-staff clef in M2ST measure 67 to treble. Notes, sounding pitches, durations, stems, voices, and staves are identical. This is an illustrative excerpt copy, not a modified model output or new benchmark result.

Ledger lines are substantially reduced, but stem comparison cannot detect the improvement. Even with full=True, Clef measures reference agreement rather than whether the easiest clef was selected. The current stem metric should be called reference stem-direction agreement, not stem appropriateness/readability. GT32 miss concerns sequence content; a more readable layout does not cancel content errors, and miss counts do not rank layouts.

3. GT53: offset-only coloring and all 11 records

Here 'worst' means the largest single-measure increase in error count from M2ST to the new model: 11 minus 3 = 8. It does not mean GT53 is the new model's sole highest-count measure; GT26 also has 11.

Only MUSTER OffsetError is colored. Blue denotes M2ST, red the new model, and purple on GT means both models err. Staff or SS-duration errors do not cause additional coloring.

OffsetER evaluates aligned ending positions, not merely onsets or direct quarterLength equality. Raw off = on + duration, after tie chains are merged; grace notes may have zero duration. The program removes miss/extra notes and orders predicted arrays by GT correspondence. For each prediction:

  1. Set its onset to the corresponding GT onset.
  2. Among all matched predicted notes, find the latest onset L not after its predicted end and the earliest onset R not before that end. The search is not restricted to a voice/staff. For simultaneous candidates, choose the closest pitch.
  3. If L/R share an onset, take the normalized end directly from L's corresponding GT onset.
  4. Otherwise apply the original formula using GT and predicted onset differences at L/R and the note's raw duration. The code uses off minus on, not off minus L.on; sign handling and integer truncation follow the original implementation.
  5. For endings beyond the final predicted onset, use the piece's final available rhythmic scale.
  6. Count an error when the normalized ending tick differs from the GT ending tick. There is no fixed beat-tolerance test; the denominator is matched GT notes.

Thus duration, ties, grace notes, neighboring onsets/correspondences, pitch-based simultaneous-anchor selection, and integer ticks can all affect offset. Staff itself does not directly enter the offset test, and staff/offset use different correspondence procedures.
